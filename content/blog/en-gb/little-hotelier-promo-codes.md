Little Hotelier promo codes live in its booking engine. Go to **Direct booking** > **Promotion codes** (classic version: **My Apps** > **Direct booking** > **Setup** > **Promotion Codes**), create a code, set a discount, the booking dates and stay dates, and link the room rates it applies to. Share it as a link with `?promotion_code=YOURCODE`. Hotelier Tools adds a page that explains each code in one sentence and warns when a code undercuts your minimum price or stacks with other discounts. You can pause a code and resume it later.

## Where are promo codes in Little Hotelier?

Promo codes belong to the booking engine on your website (direct-book.com), built on TheBookingButton. They don't change your rates in the front desk or on any channel.

- **Current version:** **Direct booking** > **Promotion codes** ([help centre](https://help-platform.littlehotelier.com/en/articles/10911579-use-promo-codes-to-create-custom-links-for-your-booking-engine)).
- **Classic version:** **My Apps** > **Direct booking**, the **Setup** tab, then the **Promotion Codes** tile ([help centre](https://helpcentre.littlehotelier.com/en/articles/8673900-set-up-and-manage-promotion-codes)).

Labels below are from Little Hotelier's help centre as of November 2026.

## How to create a promo code

1. Open **Promotion Codes** and click **Create**.
2. In **Code**, type what guests will enter. No spaces, and each code must be unique.
3. In **Description**, write the text guests see in the booking engine.
4. In **Default rate discount**, choose a percentage or an amount, and type it.
5. Set **Available From/To**: the dates on which guests can **book** with the code.
6. Set **Applicable From/To**: the nights guests can **stay** with the code.
7. Optionally tick **Hide Promo Code in reservation summary**.
8. Select the room rates the code applies to. A rate can have its own discount, which overrides the default.
9. Click **Save**.

Source: [Set up and manage promotion codes](https://helpcentre.littlehotelier.com/en/articles/8673900-set-up-and-manage-promotion-codes).

Two settings surprise people. By default, a valid code **hides all your public rates**, so the guest sees only the rates linked to the code. To change that, untick **Hide public rates when a Promo Code is applied** in **Setup** > **Properties** > **Customisation**. And the **Add Promo Code** field is always visible on the booking engine.

## How to share a promo code as a link

Guests forget to type codes. Send a link that applies the code for them. In **Promotion codes**, expand the code and click **Promotion code link** to copy it ([help centre](https://help-platform.littlehotelier.com/en/articles/10911579-use-promo-codes-to-create-custom-links-for-your-booking-engine)). The format is:

- Europe, Middle East, Africa and the Americas: `https://direct-book.com/properties/yourproperty?promotion_code=YOURCODE`
- Asia Pacific: `https://book-directonline.com/properties/yourproperty?promotion_code=YOURCODE`

A **0% code** is useful too: link it to one room type's rates and the link shows that room type only (with public rates hidden).

## Minimum stay, usage limits and first-time guests

Little Hotelier's own answers, as of November 2026 ([help centre](https://helpcentre.littlehotelier.com/en/articles/8673900-set-up-and-manage-promotion-codes)):

- **Minimum stay:** codes have none. Create a room rate with, say, a two-night minimum, link the code to it, and in the rate's **Promotions** tab choose "Show only when a linked promotional code is entered".
- **Usage limits:** there is no cap on how often a code is used. Give it an end date and change codes regularly.
- **First-time guests:** the booking engine can't tell whether a guest has booked before.
- **Public deals:** for a discount everyone sees, Little Hotelier suggests dynamic discounts or a rate multiplier for Direct booking instead of a code.

## Good practice for promo codes

- **Always set an end.** A code without booking dates lives forever, and old codes travel on coupon sites.
- **Keep booking dates and stay dates apart.** "Book this week for stays in January" is two windows, not one.
- **Know your floor.** A 15% code on a rate already discounted can drop below what a room must earn. Check the lowest night, not the average.
- **Watch stacking.** The code comes off the rate the booking engine shows. If your web rates are already below your desk rates, the guest gets both discounts.
- **One code, one purpose.** A code per campaign or partner tells you which one brought bookings.
- **Mind parity.** A code anyone can find works like a public price. Closed groups (newsletter, returning guests, a local company) are safer. Check your channel contracts.
- **Codes are direct only.** They don't reach Booking.com or Expedia, which have their own promotions.

## The faster way: every code explained, checked and paused in Hotelier Tools

Hotelier Tools reads your booking engine's codes and shows them in plain words on **Promo codes** (`/pricing/promo-codes`), under Pricing. The page is new (October 2026). Reading codes is the tested part; creating and editing them from Hotelier Tools has not yet been checked against a live booking engine, which is why every change is read back and shown as confirmed or not.

1. Open **Promo codes** and press **Read from the booking engine**. Opening the page never reads anything; the button does.
2. Each code shows its status (**Active**, **Scheduled**, **Paused**, **Expired** or **Does nothing**), a one-line summary such as "10% off the room price (not the extra-guest supplement) on 8 rates. 3. Read the warnings under each code, then use **Edit**, **Pause**, **Resume** or the delete button.

### Create or edit a code with a preview

Press **New code**. Fill in **Code** (3 to 40 letters, digits, - or _; capitals don't matter), **Discount** (**% off the rate**, up to 90%, or **Amount off the rate**), **Description**, **Booking dates**, **Stay dates** and **Rates it applies to** (**Select all public rates** ticks the usual ones). **What this code will do** shows the result before you press **Create in TheBookingButton**.

Every change is checked like this:

- The code is read fresh before the change. If someone changed it in the booking engine meanwhile, you're asked to read it again.
- The change is sent once, then read back. The result is **Confirmed**, **Differs** or **Unknown**. An unknown result is never sent again on its own: press **Read again** in **Recent changes**.
- Creating, changing, pausing and deleting need the **Publish prices** permission, because a code reaches guests at once. Deleting asks you to type the code.

### The warnings that save money

| Warning | What it means |
|---|---|
| Under your minimum price | With the discount, some nights in the next 90 days fall below your floor |
| Stacks with your apply discount | Your rates are already written below the recommendation; with the code, a web guest pays the sum |
| Hides your public rates | The code unlocks code-only rates, and a guest using it sees only those |
| Does nothing | No rate is linked: the code is accepted and the guest sees the normal price |
| Same code, other capitals | The booking engine doesn't tell `SUMMER` and `summer` apart |
| Public code | Your quotes and booking links use it, so Booking.com rate parity may count it |
| Changed outside this app | Someone edited it in TheBookingButton since the last read |

If Little Hotelier's own promotions screen (a separate system) has promotions, the page also tells you that your website doesn't use them.

### Pause and resume

The booking engine has no on/off switch for a code. **Pause** sets the code's booking dates to end yesterday and stores the old dates. The discount, rates and stay dates stay as they are, and bookings already made keep their price. **Resume** puts the stored dates back. If a code unlocks rates that are only bookable with a code, the pause dialog warns that those rates stop being bookable.

### Read every day, and ask in plain words

A scheduled task, **Read the codes every day** (06:40 by default, created automatically since November 2026), keeps the page and the assistants up to date. It only reads.

In the AI chat (beta), ask "Which codes are active?" or "What would happen if WEB gave 18%?": the assistant answers from the codes and previews a change without writing it. To change a code, it shows an approval card, and nothing happens until you approve. Developers get the same actions through the REST API (`/api/v1/pricing/promo-codes`) and MCP. Browser agents that use WebMCP can only propose: they open the filled-in form, and a person presses the button.

### See what your web really sells at

Two more places use your code:

- **Pricing settings** > **Channels & discounts** (`/pricing/settings/channels`), card **What your web really sells at**: **Check the web** reads your booking page for the next 30 nights, with and without your code, and compares it with the desk rate and what a Booking.com guest pays. It recommends a general web discount.
- **New reservation** (`/reservations/new`) shows what the same stay costs on your web, on your web with the code, and an estimate for Booking.com, next to the rates you book at.

Set the code your quotes and booking links use in **Direct-booking promo code** on the property card.

## Summary

- Little Hotelier promo codes are booking engine settings: **Direct booking** > **Promotion codes**.
- Each code has a discount, booking dates, stay dates and linked rates. By default it hides your public rates.
- Share codes as links with `?promotion_code=`. For a minimum stay, link the code to a code-only rate with that minimum.
- Give every code an end, check it against your floor, and remember codes don't reach the OTAs.
- Hotelier Tools explains each code in one sentence, warns about floors, stacking and parity, and lets you pause and resume a code without losing its settings.
